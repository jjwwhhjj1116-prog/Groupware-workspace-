# UX 13-15 최종 구현·검수 기록

## 적용 기준

- OFFDAY2 승인 기능과 데이터 흐름을 유지하고 그룹웨어 공통 셸만 확장했다.
- Google Stitch 프로젝트 `projects/6089231878104970246`의 `Tactile Command` 디자인 시스템과 신규 워크스페이스·전자결재 시안을 구현 기준으로 사용했다.
- 메신저 송수신 기능은 이번 범위에서 제외했다. 메신저 저장소는 로그인·조직·권한 구조를 파악하는 참고 자료로만 사용했다.
- 데스크톱과 모바일, 라이트와 다크 모드, KO/VI 전환 구조, 키보드 포커스와 reduced-motion을 보존했다.

## 구현 범위

- 분할형 로그인 화면, CON-COST/VIETQS 선택, 운영 API 로그인 연동 계약, 개발 검수 로그인
- L1~L5 접근등급과 역할에 따른 좌측 메뉴 노출 제어, L5 관리자 전용 설정
- 요청된 프로젝트·일정관리 계층을 포함한 통합 사이드바 및 모바일 하단 내비게이션
- 검색, 언어, 테마, 사용자 등급, 로그아웃을 통합한 헤더
- 카드별 다중 그림자, 입체 테두리, 포인터 hover lift/scale 및 reduced-motion 대응
- 전자결재 KPI, 결재함 탭, 처리 대기 문서, 결재 흐름, 빠른 도구, 월간 일정의 통합 화면
- 전자메일·드라이브·게시판·조직도·AI 챗봇 모듈 진입 화면
- 관리자 인력별 접근등급 변경 UI와 사용자 편집 접근등급

## 인력 데이터 보안

- 원본 인력현황 통합 결과는 CON-COST 33명, VIETQS 59명, 총 92명이다.
- 원본 엑셀은 `private-data/workforce/`에 로컬 보관하고 `.gitignore`로 버전관리에서 제외했다.
- 연락처, 생년월일, 비상연락처 등 민감 필드는 프런트엔드 번들에 포함하지 않았다.
- 운영 환경 권한은 `NEXT_PUBLIC_API_BASE_URL/auth/login` 로그인과 서버 API의 동일한 접근등급 검사를 함께 적용해야 한다. 프런트엔드 메뉴 숨김만으로는 보안 경계가 되지 않는다.

## 검수 결과

- 단위/워크플로 테스트: 16개 통과
- ESLint: 오류 0개
- TypeScript `--noEmit`: 통과
- Next.js production build: 통과, 정적 라우트 28개 생성
- 브라우저 데스크톱: 로그인, 워크스페이스, 전자결재, 권한관리 확인
- 브라우저 모바일: 전자결재 390px 뷰포트 및 가로 넘침 없음 확인
- 다크 모드: 권한관리 표와 카드 강조 대비 확인
- 권한 회귀: 관리자 전용 메뉴의 비관리자 미노출 및 직원 ID 로그인 확인

## 운영 연동 전 확인사항

1. 운영 인증 API가 사용자 역할, 접근등급, 부서, 담당 프로젝트 범위를 반환하도록 한다.
2. 문서·프로젝트·인력 API에서 접근등급과 소유 범위를 서버 측에서 다시 검사한다.
3. 원본 인력 엑셀을 직접 정적 제공하지 않고 승인된 서버 import 파이프라인으로만 반영한다.
